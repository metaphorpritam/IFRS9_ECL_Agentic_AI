## 2. Governing principles (inherited, unchanged)

1. **Deterministic engine first, frozen behind a gate** — no agentic code before the engine passes fixture tests.
2. **The LLM never does arithmetic** — it routes, parameterises, and narrates; every number comes from the engine.
3. **The wiki serves knowledge, never numbers** — the boundary between Tier 3 and the engine never blurs.
4. **Every scope cut is a documented simplification** in `wiki/memory/decisions.md`, never a silent omission.
5. **Ask, don't assume** at execution time (build-plan §0.2); this document proposes defaults (§7) so those
   questions are one-word confirmations, not open design debates.

## 3. Phase −1 — Repo bootstrap & reconciliation *(new; ~half a day; blocks everything)*

The build plan's Phase 0 assumes a repo that does not yet exist in the required shape. Do these in order:

### 3.1 Git + hygiene (commit #1)
- `git init` (default branch `main`).
- Commit #1 contains: `.gitignore` (`.env`, `*.key`, credentials, `data/raw/`, `node_modules/`, `.venv/`),
  `.env.example` (placeholder names only), `.gitattributes` (`* text=auto eol=lf` for scripts/Dockerfile),
  `git config core.autocrlf input`, and a gitleaks pre-commit hook **scoped to tracked files** (9P mount is slow).
- The 9P-mount mitigations from build-plan §0.4 apply verbatim — the repo is on `/mnt/d/...`, not the assumed
  `/mnt/c/...`, but it is the same mount class. All path references in scripts/config use this repo root.

### 3.2 Install the skills (first blocking task — nothing in Phase 0 works without it)
- Unzip `skills/llm-wiki.skill` → `.claude/skills/llm-wiki/` and `skills/pageindex-plus.skill` →
  `.claude/skills/pageindex-plus/` (each must contain `SKILL.md` at its top level). Commit them (project-scoped,
  auto-discovered). Keep the original `.skill` zips or delete them — they have no runtime role once installed.
- Verify: LF endings on the `.py` scripts; `uv run .claude/skills/llm-wiki/scripts/wiki_graph.py --help` runs.

### 3.3 Python project
- `uv init` · pin Python **3.13** · `uv add` core deps (pandas, numpy, statsmodels, scikit-learn, matplotlib,
  fastapi, uvicorn, python-dotenv; torch later via the cu126 index) · commit `uv.lock`.

### 3.4 Recreate the numeric ground truth (`compute_*.py`)
The notes cite eight verification scripts (`compute_ecl.py`, `compute_pd.py`, `compute_vasicek.py`,
`compute_scenarios.py`, `compute_grossup.py`, `compute_ncl.py`, `compute_rollrate.py`, `compute_validation.py`) that
**do not exist anywhere in the repo**. Rewrite them under `tests/fixtures/` from the worked-example boxes in the notes
(the target values are printed there: 12m ECL = €4,952.83 on the 5-year amortising loan; DD = 1.2116 → PD 11.28%;
D180→D90 roll-rate factor 0.60; CCF EAD €14.0m; probability-weighted ECL ≈ 1.9× base). These become the GATE's
unit-test fixtures — the engine is frozen only when it reproduces them.

### 3.5 Pre-process the notes HTML before ingestion
The flagship corpus document is hostile to naive ingestion: 1.17 MB in 689 physical lines, base64 data-URIs inline,
while `build_pageindex.py` paginates by 30-line chunks — unprocessed, the whole textbook collapses into a handful of
giant synthetic "pages" with image blobs inline, wrecking citation granularity. One-time pre-processing pass:
1. Extract the 10 base64 PNGs to files (they become proper figure cards); strip the data URIs from the HTML.
2. Convert to Markdown preserving the h2/h3 hierarchy and stable anchors (s1–s15), one heading per line, wrapped body
   lines — or run it through `ingest_notes.py`'s HTML handler and verify the output granularity.
3. Fix the stale H3 numbering in sections 12–15 (duplicate "11.1") so pageindex node titles are unambiguous.
4. Run `caption_figures.py --list` → caption the 10 figures (Gemini free-tier vision slot) → `--apply` → rebuild index.

## 6. Continuous workstream — the knowledge layer (both skills, wired concretely)

- **Session ritual (~15 min/day):** compile/update pages → `wiki_graph.py` → `wiki_log.py` (log + decisions) →
  `wiki_audit.py` clean. New-session recovery: `index.md` → last 3 log entries → audit counts. Never re-orient by
  re-reading raw sources.
- **Page taxonomy:** engine modules → `module` pages with `code:` provenance; notes §1–§4/§8–§14 → `concept` pages;
  every §3.6/§7 resolution and scope cut → `decision` pages; datasets/regulators → `entity` pages. This *is* the MDD;
  the final model-development document is an export (pageindex-plus HTML-notes pipeline), not a writing project.
- **Tier 3 is mostly pre-built:** `wiki_query.py`'s `build_graph`/scoring and `pageindex_query.py`'s
  `load`/`render_tree_for_llm`/`get_context` are importable — wrap them **in-process** as the `query_model_docs`
  LangGraph tool (no subprocess). Known limitation to accept for the demo and note in `decisions.md`: `wiki_query`
  rebuilds the graph per call; cache the graph object in the app process.
- **Retrieval vocabulary:** lexical-only retrieval needs curated aliases — seed every concept page's `aliases:` with
  the domain synonym pairs (SICR ⟷ "significant increase in credit risk", allowance ⟷ provision, PD ⟷ default
  probability, …) as pages are compiled.
- **Single-writer rule:** `wiki_log.py` and the ingest manifest do whole-file rewrites with no locking — only one
  session/agent writes the wiki at a time.

## 8. Top risks (from the adversarial cross-check) and their mitigations

1. **Skills not installed** → §3.2 is the first task; nothing in Phase 0 proceeds without it.
2. **Corpus collapses under naive ingestion** (1.17 MB / 689 lines / base64) → §3.5 pre-processing pass, verified by
   inspecting `pageindex.json` node granularity before relying on citations.
3. **Fixtures assumed but nonexistent** (`compute_*.py`) → §3.4 recreates them before the engine is written, so the
   GATE has teeth from Day 2.
4. **Silent knowledge-layer content loss** (slug collisions drop pages from retrieval; re-ingest discards figure
   captions) → audit after every compile session; keep `captions.json` in git so `--apply` is re-runnable after any
   re-ingest.
5. **No content-fidelity check exists** — hashes verify staleness, not truth → the playbook's manual semantic-lint
   pass is scheduled (end of Day 2 and Day 4), specifically diffing wiki claims against the notes corpus.
6. **Provider volatility / demo-day quota death** → failover chain (Gemma 4 31B → DeepSeek V4 Flash → Groq → local
   Ollama) built Day 1, not Day 4; verify current pricing/limits in each console before demo day (plan data is
   self-flagged "mid-2026, changes monthly").
7. **External binaries assumed present** (LibreOffice `soffice`, tesseract — needed only if PPTX/OCR sources are ever
   ingested) → not needed for the committed scope; check availability before any stretch ingestion.
8. **Agent-layer quality is unmeasured** (models have AUC/PSI; the router has nothing) → add a ~20-case routing/refusal
   test set (question → expected tier/tool/refusal) to `tests/` on Day 4; it doubles as the demo script.
9. **9P mount friction** (slow npm/git, broken inotify) → mitigations in §3.1/§4; if friction bites hard, the
   known-better alternative is moving the repo to WSL-native `~/projects/` (offer once, per build-plan §0.4).
10. **Data licensing on a public deploy** → deploy ships engine outputs and the model, never raw CRA/DCR/Freddie rows.
