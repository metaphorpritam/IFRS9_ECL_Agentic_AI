How to use this compendium

Reading order. The 13 chapters are written to be read in order once — each later chapter leans on results derived earlier (Chapter 2's survival function underpins the gross-up factor in §2.4 and the hazard model in Chapter 3; Chapter 5's PD_PIT(Z) conditioning formula is the object Chapter 6 proves is convex; Chapter 12's Merton derivation explicitly bridges back to Chapter 5's Vasicek machinery; Chapter 13 is a closing synthesis that assumes everything before it). But every chapter is also individually self-contained (its own <h1>, table of contents, and closing rule) with inline source citations, so jumping straight to one chapter via the chapter directory or the concept index below works too — you lose only the "as derived in Chapter N" cross-references, not the chapter's own self-contained argument.
Widgets. 18 chapters-worth of interactive widgets are live in this compendium (built on notes/assets/js/widgets.js, loaded relatively from each chapter) — every slider recomputes the real project formula in JavaScript (Vasicek's PD_PIT(Z,ρ), the ECL waterfall, the Jensen scenario-weight gap, hazard/seasoning curves, roll-rate and transition matrices, LGD/EAD decompositions, amortisation balances, a backtest explorer, an ROC/AUC intuition demo, and a Merton distance-to-default converter) rather than reading from a canned lookup table — drag them. Chapters 9, 10, and 13 carry no slider widget by design (product-documentation, static infra-reference, and closing-synthesis chapters respectively) but ship the same box-vocabulary (.defn/.derivation/.ex/.interpretation/.gotcha/.quiz) as every other chapter.
Data pack. Every number quoted anywhere in the compendium traces to either a fitted-model report under outputs/ or one of 133 golden fixture values in tests/fixtures/compute_*.py — the browsable version of those 133 values, plus the project's coefficient tables and scenario-weight calibration, ships as four Excel workbooks in notes/assets/data/: fixtures_all.xlsx (all 133 golden values with source anchors), dcr_coefficients.xlsx (DCR hazard/prepayment coefficients), sflld_coefficients.xlsx (Freddie SFLLD hazard/cure/severity coefficients), and scenario_weights_calibration.xlsx (DFAST paths, satellite fit, scenario-ECL summary). Regenerate with uv run --no-project notes/assets/data/build_data_pack.py after any change to a fixture module or the source reports it reads.
The app and the MDD. This compendium documents, but does not replace, two other project deliverables: the live IFRS9 ECL Copilot app (walked panel-by-panel in Chapter 9) and the Model Documentation Deliverable (walked structurally in Chapter 13 §13.6). Where a chapter and the MDD both cite a number, both trace to the same outputs/ report or fixture — neither is the "more authoritative" copy, they are two different reading paths to the same evidence.

Campaign provenance

How this compendium was built. Every chapter was produced by the same pipeline: theory text and figures pulled from the project's knowledge/ PageIndex (never re-reading the raw source notes directly), project evidence pulled from outputs/*.md reports and tests/fixtures/compute_*.py golden values (never hand-typed — every number in every .ex/.derivation box is pasted from a fixture's RESULTS dict or a report table and cited back to it), figures regenerated in themed matplotlib where the underlying data was recoverable and embedded as extracted PNGs otherwise (every generated image viewed by the authoring agent before shipping — overlapping labels and wrong-direction arrows are invisible to structural checks alone), and every chapter run through notes/assets/check_notes.py's 6-check QA gate (tag balance, image resolution, MathJax delimiter parity, no leftover template placeholders, quiz answer-reveal shape, widget JS syntax) plus a dedicated adversarial review pass per chapter batch before being counted done. The campaign ran in five batches (A: topic map + harness + Ch.1–2; B: Ch.3–5; C: Ch.6–8; D: Ch.9–11; E: Ch.12–13 + this landing page), each committed separately, with an incremental coverage re-diff against the 46-concept topic map after every batch (notes/plan/coverage.md) — the batch-C/D reports are what caught the A6/A13/A17 routing gap and the C5/C6 partial-coverage state that Chapters 12–13 were then explicitly scoped to close, verified above in the concept index.
